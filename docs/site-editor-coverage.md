# 公開サイトの編集対象と確認方法

この表の「現在の値」は固定の転記ではなく、管理画面が公開ページと同じ部品から取得する編集対象一覧を正とする。各ページで「ページ全体・検索表示 → 編集対象一覧を保存」から、表示中の文章・画像・リンク、編集場所、共通設定の影響範囲をCSVで確認できる。

## 対象ページ

| ページ | URL | 個別設定の保存先 |
| --- | --- | --- |
| TOP | `/` | `visual-editor.pages["/"]` |
| イベント | `/events/` | 同URLのページ設定。掲載イベントは既存eventsレコード |
| MENU | `/menu/` | 同URLのページ設定。CMS登録済み料理は既存menuレコード |
| 貸切・機材 | `/party/` | 同URLのページ設定。登録済みプランは既存party-plansレコード |
| アクセス | `/access/` | 同URLのページ設定。住所・電話などは共通店舗情報 |
| 初めての方へ | `/first-visit/` | 同URLのページ設定 |
| 言語別 | `/en/`・`/ko/`・`/zh-hant/`・`/zh-hans/` と各言語のevents/menu/party/access | 言語を含めたURLごとのページ設定 |

計26ページ。外部ストア内部、Googleマップ内部、Googleカレンダー内部は対象外。サイトに置くリンク、埋め込み先、枠、見出し、ボタンは対象。

## 編集入口と保存元

| 対象 | 変更 | 保存元・影響範囲 | 確認 |
| --- | --- | --- | --- |
| ヘッダー・フッター・スマホ固定ボタン | ロゴ、文章、リンク、並び順、表示、装飾 | 共通設定。言語・ページ限定への上書きも可能 | PC/スマホ、別ページ、別言語 |
| メイン画像 | 画像、スマホ専用画像、切抜位置、枚数、順番、切替秒数、重ね色 | 選択ページの画像・見た目・表示設定 | 画像を除去しても復活しないこと、PC画像を保持すること |
| 見出し・本文・注意書き・ボタン名 | 直接入力、空欄、標準へ戻す | 選択ノードの文章。住所等は共通店舗情報への入口 | 全文、長文、改行 |
| 紹介・案内・料理カード | 画像、アイコン、文章、リンク、追加、複製、並替、非表示、列数 | 静的カードはページ設定。登録済みレコードは元データの編集画面 | 追加後の個別編集、0枚、スマホ1列 |
| イベント | 登録内容、周辺の文章・ボタン、表示形式・順番 | eventsは既存登録画面。表示枠はページ設定 | 掲載予定/過去/下書き、SNS下書きとの独立 |
| 料金・プラン・PDF | 料金、文章、写真、URL、配置 | 登録済みプラン・共通機材情報とページの見た目設定 | 公開前の同一部品プレビュー |
| SNSリンク | ロゴ、表示名・ID、URL、順番、表示、大きさ、背景 | 既存店舗SNS URLは共通店舗情報。各表示はページ設定 | ブランド色を初期状態で維持 |
| 色・書体・サイズ・余白・角丸・影・装飾 | 選択式、PC/スマホ別設定 | 全ページまたは現在のページ・要素 | スマホ専用調整がPCに影響しないこと |
| 写真拡大表示 | 背景・枠、ボタン、説明、操作の表示名 | ページ全体の詳細設定 | 実ページで開く/次へ/閉じる/キーボード |
| 検索・共有 | タイトル、説明、共有画像 | ページURLごとのメタ情報 | ビルド後のHTMLのtitle/description/OG/Twitter |

## 保存と互換性

- `visual-editor` は既存compact storeの専用レコード。設定はversion 1、revision付き。従来のCMSレコードは保持する。
- 住所、電話、メール、既存店舗リンクは共通店舗情報から取得する。同じ値をページごとに保存し直さない。メールボタンの件名・本文だけはボタン単位で変更できる。
- 標準は上書きなし、空欄は明示的な空文字、非表示は専用フラグ。削除した写真・0件のカードを初期値で補完しない。「標準に戻す」は上書きの除去。
- 端末保存はlocalStorageのみ。共有保存・掲載は確認後に実行する。プレビューAPIは認証付き・読み取り専用。
- 設定の読み込み失敗・不正データは編集を停止する。公開確認失敗を成功と表示しない。設定保存後に反映処理だけ失敗した場合は、CMSを再保存せずに反映だけを再依頼する。
- ページ編集設定は最大3世代保持。「以前のページ設定を開く」で下書きに戻し、確認後に掲載する。既存のprevious形式を維持し、保存上限を超える場合は古い世代から減らす。イベント・店舗情報など別レコードの履歴ではない。コードのロールバック時は互換する設定のrevisionも確認する。
- SNS用文章は独立した下書き。コピーと投稿先を開く操作だけで、自動投稿やカレンダー同期の有効化は行わない。

## 検証入口

`npm run smoke:visual-editor` は実サービスを遮断した環境で26ページの編集対象、追加・複製・並替・非表示、空欄、画像削除、共有設定、言語の独立、プレビューの非書込み、保存競合を検証する。Playwrightの既存QAパスを指定すると直接入力・未保存確認・端末復元・PC/スマホ切替・エラーへの移動も確認する。

`npm run smoke:events:isolated` はイベント・SNS下書き・画像アップロードの既存操作を別途確認する。`BASSIC_QA_PUBLIC_SITE=1` で実際の公開ページ部品も起動して確認する。本番でテスト内容を掲載しない。

`npm run test:publish-safety` で差分確認・履歴保持・読み取り点検を検証する。公開処理は本番反映を確認した後、26ページとサイト内のリンク・画像（信頼済みmicroCMS画像ホストを含む）、管理画面のログイン保護をGET/HEADだけで点検する。外部SNS・ストアなどの内部は巡回しない。結果は既存のGitHub Actionsに記録し、失敗時はジョブを失敗として扱う。独立した通知サービスや連絡先は追加しない。
