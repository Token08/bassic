# 掲載イベント未定での運用テスト

確認日: 2026-11-11

実際に掲載するイベントが決まる前でも、架空のイベントを使って運用の流れを検証できる。本番CMS、本番カレンダー、SNSへの書き込みは行っていない。

## 今回確認できたこと

- 隔離した管理画面でログイン、Facebook取り込み、既存イベントの選択、下書き保存、公開処理を実行した。
- 公開処理に使う外部サービスの応答はメモリ内の代替サービスに限定し、隔離した公開ページでタイトル・開始時刻・画像とスマホ表示を確認した。非公開イベントが表示されないことも確認した。
- 同じイベントを再取り込みしてもイベントとX・Instagram用下書きが増えず、スタッフが編集した文面を保持することを確認した。
- 画像を取得できない場合に既存画像を保持し、カレンダーやSNSの処理失敗をサイト公開の結果と分けることを確認した。
- 実際の同期関数をメモリ内のカレンダーで実行し、追加→日時変更→再実行で同じ予定を更新すること、非公開化などで同期対象から外れても既存予定や手動登録の予定を勝手に削除しないことを確認した。
- 日時の日本時間への変換、OPENとSTARTの区別、曖昧な時刻の空欄維持、通信失敗後の再実行など、関連する自動テスト19件が成功した。
- 過去のBassic実イベント `https://www.facebook.com/events/5208864859197487/` を読み取り専用で取得し、タイトル・日付・画像を照合した。このページの開始時刻は取得できず、スタッフ入力が必要と判定された。

PlaywrightとChromeは別途必要。Facebookの読み取り確認はネットワークと対象ページの取得可否に依存する。

## 接続後に確認すること

実Googleカレンダーの権限、Googleの実API応答、本番サイトへの実イベントの掲載、スタッフ本人による単独操作は今回の隔離テストでは確認していない。

Googleカレンダーは店舗の共有先と権限を確認後、専用の非公開カレンダー `Bassic QA (private)` で `scripts/verify-calendar-test-write.mjs` を実行する。このスクリプトは追加・日時変更・再実行を検証し、作成したテスト予定を削除する。掲載イベントが未定でも実行できる。本番用カレンダーをこのテストの対象にはしない。

個人用Googleアカウントは店舗用の接続検証に使用しない。個人用アカウントで実施した操作を、店舗カレンダーの書き込み権限確認の証拠として扱わない。

## 運用前レビューで追加した検証

- Facebook読み取り中のURL変更: 旧URLの遅延応答を捨て、入力中の新URLを保持する。
- 画像取得失敗: 画像を表示できない旨と、画像URL確認・再アップロードの操作を表示する。
- SNS作成途中の通信失敗: 一つ目の下書きの保存後にエラーを返し、再実行で不足する投稿先だけが作られること、編集済み文面が残ることを確認する。
- SNS単独復旧: 実際の管理画面の復旧ボタンで、サイト公開依頼を増やさずSNS下書きを作成する。最新の保存済み日時を使い、非公開化したイベントは拒否する。
- 公開・SNS再作成ボタンの連打でも処理を一度だけ進める。投稿先ごとの作成結果が欠けた応答は成功表示にしない。
- STARTを入力欄で消した場合、依頼メモにも未入力と表示してコピーを止める。再取り込みでSTARTが取得できなかった場合は、手入力済みのSTARTを消さない。
- カレンダー照合失敗・重複・中止済み予定: 成功表示を出さない。
- 公開ページ: 縦長画像、横長画像、画像なし、長い英数字のイベント名を320・390・768・1440px幅で表示し、横スクロールがないこととスマホの一列配置を確認する。

## 公開準備の判断

Facebook連携のドラフトPR #4で管理し、管理画面と公開サイト側のCSSを同じ変更として反映する。Googleカレンダー定期同期とSNS自動投稿は有効にしない。Vercel Previewでは本番CMSへの書き込みが禁止されているため、書き込みを伴う操作確認はローカルの隔離環境で行う。

リリース前に管理画面・公開サイトのビルド、関連テスト、隔離したPC・スマホ操作、PRの変更内容を確認する。リリース後はテストイベントを作らず、ログイン、既存データ表示、画像、編集・プレビューへの移動を確認する。問題時は管理画面を直前のVercelデプロイに戻し、公開サイトは対象コミットをrevertして既存公開処理で反映する。

店舗用カレンダー権限と店舗スタッフ本人の単独操作は、引き続き未確認。技術テストの成功と店舗での運用開始確認を区別する。

## PMレビューの確認先

| 対象 | 確認方法・成果物 |
| --- | --- |
| 取り込み失敗時の案内・入力保持 | 隔離ブラウザテストの未取得応答、遅延応答、壊れた画像、START変更 |
| サイト・カレンダー・SNSの独立した結果表示 | 隔離APIとブラウザでSNSエラー中もサイト公開成功、カレンダー未掲載・差分・通信エラー、SNS結果欠落を確認 |
| 写真とスマホ表示 | 縦長・横長・画像なし・長い名前を4種類の画面幅で確認 |
| 一人で行う操作の導線 | ログイン→取り込み→既存イベント選択→下書き→プレビュー→公開→X・Instagramコピーの自動操作。店舗本人の使いやすさの評価は別途必要 |
| 復旧・重複防止 | 部分保存後の再実行、入力保持、公開とSNS復旧の連打、カレンダー再実行の自動テスト |
| 公開準備 | `npm run check:handoff` 成功、ドラフトPR #4、導入・復旧手順、カレンダー同期とSNS自動投稿の無効維持 |
