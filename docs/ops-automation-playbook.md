# 運用省力化プレイブック

月次レポートは対象外です。日々のSNS・イベント・問い合わせ・公開確認の手間を減らすため、以下を標準運用にします。

## 公開処理と外部連携の分離（2026-11-06）

サイト公開は `Deploy to GitHub Pages`、外部への書き込みは `External operations` で別々に実行します。外部連携の障害はサイトのビルド・公開を停止させません。

外部連携は接続先と実動作の検証が済んだものから、GitHub Actions Variablesで個別に有効化します。未設定時は実行しません。

| 設定 | `true` にした時の動作 |
| --- | --- |
| `ENABLE_CALENDAR_SYNC` | Google Calendar同期。書き込み認証が必要。既存予定の一括削除は無効 |
| `ENABLE_SOCIAL_PUBLISHING` | 承認済みSNS下書きの配信。媒体ごとの認証が必要 |
| `AUTO_ARCHIVE_PAST_EVENTS` | 過去の公開イベントを非公開にする |

外部連携は毎時42分（UTC）と手動実行に対応します。公開ボタンはサイト更新だけを依頼し、SNS投稿は次回の外部連携処理で実行します。
CMSのイベント取得が失敗した場合、カレンダー同期は停止します。SNS配信が失敗した場合は失敗を保存し、ワークフローも失敗として通知します。
GitHubの標準失敗通知をリポジトリ所有者が受け取れることを引き渡し時に確認します。長期間リポジトリに更新がない場合のスケジュール停止にも注意し、停止時はActions画面から再有効化します。

## 1. イベント起点のSNS下書き

1. FacebookイベントURLを管理画面のイベントに貼る。
2. Facebookから読み取り、日付とSTARTを確認する。
3. プレビューして公開する。
4. `social-notices` に Facebook / Instagram / X の投稿下書きが作られる。
5. SNS投稿文を確認し、問題なければ `SNS配信状態` を `投稿承認済み` にする。

投稿済みIDが入ったものは再投稿されません。

## 2. SNS投稿テンプレ

イベント下書きは以下を自動で含めます。

- イベント名
- 日付
- START
- 出演者
- 予約/詳細URL
- X向けハッシュタグ

文面を少し直して承認するだけで投稿できます。

## 3. 公開後チェック

GitHub Actionsでビルド後に以下を自動実行します。

```bash
npm run smoke:links
npm run smoke:content
npm run smoke:seo
```

リンク切れ、主要文言抜け、SEO基本項目が失敗した場合は公開ワークフローが止まります。

## 4. 過去イベント整理

`AUTO_ARCHIVE_PAST_EVENTS=true` をGitHub Actions Variablesに設定すると、公開済みイベントのうち、先々月以前のイベントを自動で非公開にします。先月・当月・次月以降のイベントは残ります。

推奨値:

```text
AUTO_ARCHIVE_PAST_EVENTS=true
```

これで、基本的に「先月・当月・次月のイベント」はHP上で確認できます。

## 5. Googleビジネスプロフィール確認

HPやイベントの公開後、以下だけ確認します。

- 営業時間がHPと一致している
- イベント営業日や貸切日が必要なら投稿/最新情報へ反映されている
- 住所、電話、公式サイトURLがHPと一致している
- 新しいイベント画像や店内写真を追加できる時は追加する
